# JCC Visualiser — Full Build Specification

**Read this entire document before writing any code. This is the complete source of truth for the build.**

---

## 1. Project overview

JCC Visualiser is a focused web application for understanding the Japan Crude Cocktail (JCC) — the volume-weighted CIF average price of all crude oil that clears Japanese customs each month, published by the Petroleum Association of Japan (PAJ) from Ministry of Finance / Japan Customs data.

The product has four surfaces, mapped 1-to-1 to the user's research goals:

1. **Composition** (`/composition`) — past crude grades that made up the JCC basket and how that mix has evolved month-by-month over 10+ years.
2. **Grades** (`/grades`) — the individual constituent grades, each with its historical price path, share-over-time, and physical specs. Lets the operator drill from "what's in the basket" to "what's it worth."
3. **Annotations** (layered onto Composition and Grades) — curated event markers explaining *why* the basket looks the way it does at any moment (Iran sanctions, Russia invasion, Hormuz crisis, OPEC+ cuts, Murban exchange launch, etc.).
4. **Forward curve** (`/curve`) — the current JCC forward curve from CME futures, recent-weeks overlay showing curve evolution, and a decomposition into the underlying benchmark forwards (Dubai / Oman / Murban / Brent) plus residual basis. Also makes the 4–5 month physical-to-LNG lag explicit.

Plus a thin landing page (`/`) showing the latest JCC value with publication status, a composition snapshot, a curve thumbnail, and the most recent curated events.

The product is a **research and explanation tool**, not a trading product. There is no AI agent, no backtest, no forecasting model, no per-user accounts in v1.

The dataset is real: PAJ monthly JCC values back to the 1990s, Japan Customs Trade Statistics back to at least 2015, daily benchmark settlements back to inception of each contract.

## 5. Database schema

Single migration: `supabase/migrations/001_init.sql`.

Units are non-negotiable: **¥/kl for JCC official price (Japan's native unit), USD/bbl for benchmark spot and futures, % for shares, kl (kilolitres) for volumes**. Conversion factor: 1 bbl = 0.158987 kl. JPY↔USD conversion is via daily FX (Frankfurter ECB feed, fetched as part of benchmarks ingest).

No RLS. Single-operator dashboard. RLS deferred to v2 if multi-user comes in scope.

```sql
-- =========================================================
-- 001_init.sql — JCC Visualiser schema
-- =========================================================

-- Reference: crude grades that have ever appeared in the JCC basket.
create table grades (
  id              text primary key,                 -- snake_case slug, e.g. 'murban'
  display_name    text not null,                    -- 'Murban'
  origin_country  text not null,                    -- ISO 3166-1 alpha-2, e.g. 'AE'
  region          text not null check (region in ('middle_east','russia','americas','africa','asia_pacific','europe','other')),
  api_gravity     numeric(5,2),                     -- degrees API
  sulphur_pct     numeric(5,3),                     -- weight %
  type            text not null check (type in ('light_sweet','light_sour','medium_sweet','medium_sour','heavy_sweet','heavy_sour')),
  first_seen_in_jcc date,                           -- populated by derive_composition
  last_seen_in_jcc  date,
  notes           text,                             -- curator notes
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);

-- Raw Japan Customs monthly imports. One row per (month, HS code, origin).
create table imports_monthly (
  month           date not null,                    -- first-of-month UTC
  hs_code         text not null,                    -- e.g. '2709.00.900'
  origin_country  text not null,                    -- ISO 3166-1 alpha-2
  volume_kl       numeric(14,3) not null,
  value_jpy       numeric(18,0) not null,           -- CIF value in JPY
  source          text not null default 'customs',
  ingested_at     timestamptz not null default now(),
  primary key (month, hs_code, origin_country)
);

-- Derived: composition of the JCC basket by grade for each month.
-- Populated by derive_composition.py joining imports_monthly with grade_hs_mapping.
create table composition_monthly (
  month           date not null,
  grade_id        text not null references grades(id),
  volume_kl       numeric(14,3) not null,
  value_jpy       numeric(18,0) not null,
  share_pct       numeric(6,3) not null,            -- volume share of the month's basket, 0–100
  source          text not null default 'derived',
  ingested_at     timestamptz not null default now(),
  primary key (month, grade_id)
);

-- Official JCC monthly value as published by PAJ.
create table jcc_monthly (
  month           date primary key,
  jcc_value_jpy_per_kl  numeric(12,2) not null,
  jcc_value_usd_per_bbl numeric(10,4),              -- derived using monthly avg FX
  status          text not null check (status in ('provisional','revised','final')),
  source          text not null default 'paj',
  source_url      text,
  ingested_at     timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);

-- Daily benchmark spot / settlement prices.
create table benchmark_prices_daily (
  date            date not null,
  benchmark       text not null check (benchmark in ('dubai','oman','murban','brent','wti','arab_light','arab_medium','arab_heavy','arab_extra_light','espo','opec_basket','jpy_usd_fx')),
  price_usd_bbl   numeric(10,4) not null,           -- for FX row this stores JPY per USD
  source          text not null,                    -- 'cme', 'ice', 'eia', 'opec', 'frankfurter'
  ingested_at     timestamptz not null default now(),
  primary key (date, benchmark)
);

-- Daily benchmark forward curve snapshots.
create table benchmark_forwards_daily (
  settlement_date date not null,                    -- date the settlement was taken
  benchmark       text not null check (benchmark in ('dubai','oman','murban','brent','wti')),
  contract_month  date not null,                    -- first-of-month for the contract delivery month
  price_usd_bbl   numeric(10,4) not null,
  source          text not null,
  ingested_at     timestamptz not null default now(),
  primary key (settlement_date, benchmark, contract_month)
);

-- Daily CME JCC futures settlement curves.
create table jcc_futures_daily (
  settlement_date date not null,
  contract_month  date not null,
  price_usd_bbl   numeric(10,4) not null,
  open_interest   integer,
  volume          integer,
  source          text not null default 'cme',
  ingested_at     timestamptz not null default now(),
  primary key (settlement_date, contract_month)
);

-- Curated geopolitical / market events for annotation.
create table events (
  id              text primary key,                 -- slug, e.g. 'iran_sanctions_snapback_2018'
  date_from       date not null,
  date_to         date,                             -- null = point-in-time event
  category        text not null check (category in ('sanctions','geopolitics','supply_shock','demand_shock','opec_decision','contract_launch','disaster','policy')),
  title           text not null,
  description_md  text not null,                    -- markdown body for hover-card / detail
  impact_grades   text[] not null default '{}',     -- array of grades.id this event affected
  sources         text[] not null default '{}',     -- URLs
  created_at      timestamptz not null default now()
);

-- Curated lookup loaded from data/seed/grade_hs_mapping.yaml.
-- Used by derive_composition.py to split (HS code, origin country) → grades and weights.
-- weight_pct in each (hs_code, origin_country) tuple should sum to 100 within a validity window.
create table grade_hs_mapping (
  hs_code         text not null,
  origin_country  text not null,
  grade_id        text not null references grades(id),
  weight_pct      numeric(5,2) not null,            -- 0–100
  applies_from    date not null,                    -- inclusive
  applies_to      date,                             -- nullable = open-ended
  notes           text,
  primary key (hs_code, origin_country, grade_id, applies_from)
);

-- Audit log of every ingest / derivation run.
create table compute_runs (
  id              uuid primary key default gen_random_uuid(),
  kind            text not null,                    -- 'ingest_paj' | 'ingest_customs' | 'ingest_benchmarks' | 'ingest_jcc_futures' | 'derive_composition'
  status          text not null check (status in ('running','success','error')),
  started_at      timestamptz not null default now(),
  finished_at     timestamptz,
  duration_seconds numeric(10,2),
  row_count       integer,
  error_message   text,
  output_jsonb    jsonb                             -- free-form per-job structured output
);

-- Indexes that pay for themselves on the read patterns we know about.
create index idx_imports_monthly_origin on imports_monthly(origin_country);
create index idx_composition_monthly_grade on composition_monthly(grade_id);
create index idx_benchmark_prices_daily_benchmark on benchmark_prices_daily(benchmark);
create index idx_benchmark_forwards_settlement_benchmark on benchmark_forwards_daily(settlement_date, benchmark);
create index idx_jcc_futures_settlement on jcc_futures_daily(settlement_date);
create index idx_events_date_from on events(date_from);
create index idx_compute_runs_kind_started on compute_runs(kind, started_at desc);
```

## 6. Routes and UI surfaces

### 6.1 `/` — Landing

Top: latest JCC value (¥/kl + USD/bbl), month, publication status badge (`provisional` / `revised` / `final`). Below: three thumbnails linking to Composition, Grades, Curve. Right rail: recent events feed (last 5 from `events` table). Server Component; reads from Supabase directly.

### 6.2 `/composition` — Composition over time

- **Primary chart:** 100%-normalised stacked area chart, x-axis = month from earliest available data to latest, y-axis = share %, one stacked band per grade. Recharts `<AreaChart>` with `stackOffset="expand"`.
- **Toggle:** view mode — *by grade* (default), *by origin country*, *by region* (middle_east / russia / americas / africa / etc.).
- **Date scrubber:** a draggable cursor on the time axis; selecting a date renders a treemap snapshot (or pie) of the basket on that month in a side panel.
- **Event timeline:** sidebar (left) listing curated events chronologically. Hovering an event highlights its date on the main chart with a vertical reference line; clicking opens a detail card with `description_md` and sources.
- **Volume toggle:** optional secondary view showing absolute volumes (not normalised) so the operator can see total Japanese crude import growth/decline.

Client Component for chart interactivity; data fetched server-side via the App Router's `loading.tsx` boundary, hydrated to TanStack Query.

### 6.3 `/grades` — Grade index

Index page: a table of all grades in `grades`, columns: name, origin, region, type, API, sulphur, first-seen, last-seen, current-share (latest month). Sortable. Each row links to `/grades/[gradeId]`.

### 6.4 `/grades/[gradeId]` — Per-grade detail

- **Header:** display name, origin flag, region, specs (API, sulphur, type), curator notes.
- **Price history line:** multi-year line chart of relevant benchmark price (from `benchmark_prices_daily`; the grade's primary benchmark is recorded in `grades.notes` or inferred — e.g. Murban → murban benchmark, Arab Light → arab_light, ESPO → derived from oman+premium).
- **Share-over-time sparkline:** monthly `composition_monthly.share_pct` for this grade, from `first_seen_in_jcc` to `last_seen_in_jcc`.
- **Why it's used:** events from `events` where `grade_id ∈ impact_grades`, rendered as a vertical timeline of cards.

### 6.5 `/curve` — Forward curve

- **Current curve:** line chart of latest `jcc_futures_daily` row (x = contract_month, y = price_usd_bbl).
- **Recent-weeks overlay:** previous N weeks' settlements rendered as faded lines on the same axes, showing curve evolution.
- **Decomposition view:** for the current curve, render a stacked-area chart attributing each contract month's price to Dubai / Oman / Murban / Brent contributions (using fitted weights from a simple linear regression of `jcc_futures_daily` ~ `benchmark_forwards_daily`), with a "residual basis" stack on top. Operator-friendly explanation panel below the chart.
- **Lag diagram:** a static SVG illustration of the physical → customs → PAJ → LNG indexation timeline (~4–5 months end-to-end), with a tooltip per stage.

### 6.6 `/api/cron/ingest-*` — Cron endpoints

Four POST routes, secured by `CRON_SECRET` header check. Each invokes the corresponding Python ingest script (mechanism finalised at M3 — likely `child_process.spawn` if Vercel Cron supports a Python runtime bundle, otherwise the route just enqueues a job for an external worker; fallback is a GitHub Action cron that runs the Python scripts directly on a schedule and writes to Supabase). Returns a JSON summary of the resulting `compute_runs` row.

## 7. Ingestion pipeline

All ingest jobs live in `apps/ingest/ingest/`. Each writes to Supabase using the service-role key.

### 7.1 Sources and schedules

| Job | Source | URL pattern | Schedule | Tables written |
|---|---|---|---|---|
| `paj` | Petroleum Association of Japan statistics + e-Stat API mirror | `paj.gr.jp/english/statis` + `api.e-stat.go.jp` | Monthly, 8th of month 09:00 UTC | `jcc_monthly` |
| `customs` | Japan Customs Trade Statistics (HS codes 2709.00.100, 2709.00.900, 2710.19.xxx for 7 codes) | `customs.go.jp/toukei` CSV downloads via e-Stat API | Monthly, 8th of month 09:30 UTC | `imports_monthly` |
| `benchmarks` | CME (Dubai, Murban), ICE (Brent, Oman), EIA API (WTI spot + Brent spot + JPY/USD via frankfurter), OPEC basket | per-source, all free | Daily 06:00 UTC | `benchmark_prices_daily`, `benchmark_forwards_daily` |
| `jcc_futures` | CME JCC futures daily settlement | `cmegroup.com/markets/energy/.../japan-crude-cocktail.settlements` | Daily 22:00 UTC (after CME settles) | `jcc_futures_daily` |
| `derive_composition` | Internal — joins `imports_monthly` with `grade_hs_mapping` | (none, DB only) | After `customs` completes | `composition_monthly`, also updates `grades.first_seen_in_jcc` / `last_seen_in_jcc` |

Historical backfill at M3:
- `jcc_monthly` — back to 2000-01 (PAJ publishes earlier; we cap at 2000).
- `imports_monthly` — back to 2015-01 (older Japan Customs data exists but format changes complicate it; v1 horizon is 2015+).
- `benchmark_prices_daily` — back to each contract's inception (Murban → 2021-03, others → 2010+).
- `jcc_futures_daily` — back to CME JCC futures inception (~2010).

### 7.2 Required behaviour for every ingest job

Non-negotiable. Every job in `apps/ingest/ingest/*.py` (except `healthcheck.py`) implements:

1. **Idempotent UPSERT.** Every write uses `ON CONFLICT DO UPDATE` so a re-run never doubles up. Primary keys defined in §5 are designed for this.
2. **Pydantic validation.** Every row is validated by a `pydantic.BaseModel` subclass before write. Validation failures are logged with row context to `compute_runs.output_jsonb` and skipped — the batch does not abort.
3. **Polite retry.** Exponential backoff on transient HTTP errors (5 retries, 2× factor, jitter; via `tenacity` or hand-rolled in `common.py`). 429 / 503 trigger longer backoff. Non-retryable errors (404, 401, malformed source) bubble up and fail the run cleanly.
4. **Audit.** Every run begins with a `compute_runs` insert (`status='running'`) and ends with an UPDATE (`status='success'|'error'`, `finished_at`, `duration_seconds`, `row_count`, `error_message`). Crash-safe via try/finally.
5. **Locking.** Each job acquires a Postgres advisory lock on `pg_try_advisory_lock(hashtext('ingest_<job>'))` to prevent overlapping runs. If the lock is held, the job logs a single line and exits cleanly (this is normal during long backfills).

`common.py` provides shared helpers — `with_lock(name)` context manager, `audit_run(kind)` decorator, `upsert(table, rows, conflict_cols)` wrapper, `retry_get(url, **kw)` polite-retry HTTP wrapper.

### 7.3 Derivation: `composition_monthly`

After `customs` completes, `derive_composition.py` runs:

1. For each `(month, hs_code, origin_country)` row in `imports_monthly` for months not yet in `composition_monthly`:
2. Look up matching rows in `grade_hs_mapping` where `month` falls within `[applies_from, applies_to)`.
3. If no mapping is found for a `(hs_code, origin_country)` tuple, log a warning to `compute_runs.output_jsonb` and assign the volume to a synthetic `grade_id = 'unmapped_<origin_country>'`. (This makes mapping gaps visible in the UI rather than silently dropped.)
4. Distribute the row's volume + value across the matched grades by `weight_pct`.
5. UPSERT into `composition_monthly`. Compute `share_pct` per `(month, grade_id)` as that grade's volume divided by the month's total volume × 100.
6. Update `grades.first_seen_in_jcc` and `grades.last_seen_in_jcc` based on observed presence.

The `grade_hs_mapping` YAML is the single point of curatorial decision. Editing it and re-running the derivation re-computes history without re-fetching from Customs.
